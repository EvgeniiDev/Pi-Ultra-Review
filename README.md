# Pi Ultra Review

Плагин для [Pi](https://github.com/earendil-works/pi-coding-agent): параллельное ревью кода сразу несколькими моделями.

## Проблема

Ревью одной моделью — это всегда одна точка зрения. Она может пропустить уязвимость, не заметить проблему с производительностью или просто ошибиться. А гонять код по моделям по очереди — долго.

## Решение

Плагин отправляет ваш код на ревью **сразу нескольким моделям одновременно** — каждая смотрит код со своей стороны. Ревьюеры — агенты: вместо того чтобы заливать файлы целиком, они **сами читают нужные файлы по частям** (тул `read_file`, построчно) и выносят вердикт. Все ревью собираются в один отчёт с итоговым вердиктом.

Как это работает:

- Каждый ревьюер получает **общий префикс промпта** (манифест файлов + дифф + trust boundary) и свою роль. Общий префикс идентичен для всех спеков — prefix-кэш провайдера отдаёт его как cache hit.
- Все вызовы одного прогона идут с **общим `sessionId`** — при session-affinity маршрутизации спеки попадают на тёплый узел с разогретым кэшем.
- Модель читает файлы через `read_file` по чанкам, ищет дубли через `search_files` (simplify) и выдаёт вердикт строго по JSON-контракту.
- Пустой или «тул-зацикленный» ответ: до двух ноджей (второй — с готовым JSON-шаблоном), затем ретрай **той же беседы** — файлы не перечитываются, кэш-префикс сохраняется.
- Финальный проход судьи (`judge`) дедуплицирует находки и отсекает галлюцинации.

### С каких ракурсов идёт ревью

Каждое направление — отдельный «субагент» со своей ролью и зоной ответственности:

**🔐 Security — безопасность**
Роль: инженер по безопасности, адверсальное ревью. Ищет эксплуатируемые уязвимости: инъекции (SQL, command, template, path…), обходы аутентификации и авторизации, повышение привилегий, утечки секретов, проблемы по OWASP.

**🎯 Correctness — корректность**
Роль: старший инженер по анализу корректности и отказов. Ищет инвертированную логику, off-by-one, неверные предположения и краевые случаи (null, пустые значения, ноль, отрицательные, переполнения, NaN), гонки и состояния.

**⚡ Performance — производительность**
Роль: инженер по производительности продакшена. Ищет измеримые регрессии: алгоритмические деградации (O(n²) и хуже), N+1 запросы к БД/сети/ФС, утечки памяти, блокирующий I/O.

**🧱 Maintainability — поддерживаемость**
Роль: staff-инженер, оценивает долгосрочную изменяемость и ясность архитектуры. Ищет дублирование бизнес-логики, функции/классы со множеством ответственностей, лишнюю сложность, мёртвый код.

**🎨 Style — стиль и идиоматика**
Роль: эксперт по языку и фреймворку. Ищет вводящие в заблуждение имена, неидиоматические паттерны, которые затемняют намерение, проблемы читаемости.

**🛠️ Best Practices — инженерная надёжность**
Роль: старший продакшн-инженер. Ищет проглоченные ошибки, операции без таймаутов и отмены, нарушения принципов (SOLID, DRY), риски надёжности и расширяемости.

**🧹 Simplify — упрощение и уборка**
Роль: специалист по упрощению кода. Ищет то, что можно безопасно удалить /
встроить / рефакторить / распараллелить, и reuse-возможности по всему
репозиторию (не только в диффе). Находки несут risk (safe / confirm / review)
и action (delete / inline / refactor / parallelize); reuse-находки указывают
существующий символ в поле reuseTarget. Спеку выдан инструмент search_files
для поиска существующих хелперов и дублей вне диффа. CRITICAL не выдаёт —
cleanup-находки LOW/MEDIUM не блокируют merge; редкие HIGH трактуются по
общей калибровке как release-blocking.

Каждый субагент возвращает вердикт (approved / requires changes / rejected) и уровень риска. В режиме deep один субагент прогоняется сразу несколькими моделями — для снижения ложных срабатываний.

## Установка

```bash
pi install git:github.com/EvgeniiDev/Pi-Ultra-Review
```

После установки перезапусти Pi (или `/reload`) — команда `/ultra-review` станет доступна.

## Совместимость

Проверено и работает на **Pi 0.83.0**. Версия ниже может работать, но не гарантируется.

Рекомендуемая модель: **`opencode-go/deepseek-v4-flash`** — плагин заточен под её возможности: 1M контекст, max reasoning, 384K max output.

> Free-модели (zen-relay) на `main` не поддерживаются — версия с их костылями живёт на ветке [`free-model-support`](https://github.com/EvgeniiDev/Pi-Ultra-Review/tree/free-model-support).

## Как пользоваться

### Мастер

В Pi: команда `/ultra-review` — интерактивно выбираете скоуп, направления и модели, deep-режим и проход судьи.

### Инструмент

```ts
ultra_review({ scopeId, specIds, modelIds, deep, judge? })
```

Параметры:

- `scopeId` — что ревьюить:
  - `working_tree` — незакоммиченные изменения
  - `current_dir` — все файлы директории (агенты читают по требованию)
  - `branch_vs_<base>` — дифф ветки vs base, например `branch_vs_origin/main`; префикс `branch_vs_` матчит веточный скоуп
  - `last_commit` — файлы последнего коммита
- `specIds` — направления из списка выше (`security`, `correctness`, `performance`, `maintainability`, `style`, `best_practices`, `simplify`)
- `modelIds` — модели форматом `provider/modelId`
- `deep` — полная матрица модели × спеки (true) или round-robin (false)
- `judge` — финальный проход судьи: дедупликация и валидация находок (рекомендуется)

Отчёт сохраняется в `reviews/` (gitignored).

## Конфигурация

Все настройки — в `extensions/ultra-review/constants.ts`:

| Константа | По умолчанию | Что делает |
|---|---|---|
| `REASONING_EFFORT` | `"max"` | Уровень reasoning для всех моделей |
| `MODEL_MAX_TOKENS` | `65536` | Бюджет выходных токенов (64K — под мышление на max reasoning) |
| `MAX_DIFF_CHARS` | `100_000` | Кап диффа в промпте (~25K токенов; 100K покрывает обычные ветки целиком) |
| `MAX_AGENT_ITERATIONS` / `MAX_AGENT_TOOL_CALLS` | `10` / `40` | Бюджет агента (кумулятивен на все ретраи) |
| `PROVIDER_MAX_CONCURRENCY` / `GLOBAL_MAX_CONCURRENCY` | `4` / `10` | Параллельность к одному провайдеру / всего |
| `EXTRA_MODELS` | `["opencode-go/deepseek-v4-flash"]` | Модели, показываемые в мастере первыми |
| `BLOCKED_PROVIDERS` | `["openrouter"]` | Провайдеры, скрытые из мастера; очистить массив — вернуть |

Если провайдер не принимает какой-то параметр (`reasoning_effort`, `max_tokens`, session-заголовки) — плагин автоматически деградирует: повторит вызов без него.

## Догфуд

Плагин ревьюит сам себя: `scopeId "branch_vs_main"` + все спеки (кроме security) — итоги последнего прогона: 6/6 задач, судья отсеял 4 false positive из 22 находок, все реальные баги исправлены.
